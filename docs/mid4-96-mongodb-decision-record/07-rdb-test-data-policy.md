# RDB 테스트 데이터 생성 기준

[상위 문서](./README.md) | [이전: 후속 적용 검토 흐름 및 결론](./06-final-flow-and-conclusion.md) | [다음: RDB 조회 성능 측정 시나리오](./08-rdb-performance-test-scenarios.md)

## 목적

이 문서는 활동내역 조회 기능을 RDB 기준으로 먼저 구현하고 검증하기 위한 테스트 데이터 기준을 정리한다.

MongoDB Read Model용 데이터를 먼저 만들지 않는다. MongoDB 적용 여부는 RDB 구현, 인덱스 최적화, 성능 검증 이후 가장 병목이 큰 조회 기능을 기준으로 판단한다.

테스트 데이터는 두 종류로 나눈다.

```text
정확성 검증용 데이터
-> 조회 결과, 정렬, 제외 조건을 눈으로 확인할 수 있는 작은 데이터

성능 검증용 데이터
-> 100k / 1m / 10m seed scale에서 RDB 조회 병목을 측정하기 위한 대량 데이터
```

## 공통 데이터 원칙

테스트 데이터는 다음 도메인 데이터를 포함한다.

```text
- 사용자
- 관심사
- 관심사 구독
- 뉴스 기사
- 댓글
- 댓글 좋아요
- 뉴스 기사 조회 이력
```

데이터 생성 기준은 재현 가능해야 한다.

```text
- 같은 seed 값으로 같은 데이터가 생성되어야 한다.
- k6에서 반복 조회할 수 있도록 대표 사용자 ID를 고정한다.
- 정상 데이터와 제외 데이터를 함께 만든다.
- 생성 후 데이터 규모와 대표 사용자별 활동 건수를 확인할 수 있어야 한다.
```

조회 반환 기준은 다음과 같다.

```text
구독 중인 관심사
-> 서버 응답은 현재 구독 중인 전체 목록 반환
-> 프론트 화면 표시 개수와 별도로 판단

최근 작성 댓글
-> 댓글 작성 시각 기준 최신순
-> 최대 10건

최근 좋아요한 댓글
-> 좋아요 발생 시각 기준 최신순
-> 최대 10건

최근 조회 기사
-> 조회 시각 기준 최신순
-> 최대 10건
-> 같은 기사는 중복 항목을 만들지 않고 최신 조회 시각만 반영
```

삭제 상태 검증 기준은 다음과 같다.

```text
논리삭제 대상
-> 사용자, 기사, 댓글
-> RDB 원본에는 남아 있지만 활동내역 조회에서는 제외
-> MongoDB Read Model에서는 visible=false와 status로 숨김 처리

물리삭제 대상
-> 사용자, 기사, 댓글
-> RDB 원본에서 최종 제거된 뒤 MongoDB Read Model에서도 관련 문서 제거
-> 물리삭제 이후에는 복구 대상 아님
```

## 정확성 검증용 데이터

정확성 검증용 데이터는 기능 테스트와 API 응답 검증에 사용한다. 데이터 건수보다 케이스 식별 가능성을 우선한다.

### 대표 사용자

| 사용자 | 목적 |
| --- | --- |
| `user-empty` | 활동내역이 없는 사용자 |
| `user-interest` | 관심사 구독 조회 검증 사용자 |
| `user-comment` | 최근 작성 댓글 조회 검증 사용자 |
| `user-like` | 최근 좋아요한 댓글 조회 검증 사용자 |
| `user-article-view` | 최근 조회 기사 검증 사용자 |
| `user-mixed` | 여러 활동이 함께 있는 통합 검증 사용자 |
| `user-deleted` | 논리삭제된 사용자 활동 제외 검증 사용자 |

### 구독 중인 관심사 조회

| 케이스 | 데이터 구성 | 기대 결과 |
| --- | --- | --- |
| 구독 없음 | `user-empty`가 관심사를 구독하지 않음 | 빈 목록 반환 |
| 구독 1건 | `user-interest`가 관심사 1개 구독 | 해당 관심사 반환 |
| 구독 여러 건 | `user-interest`가 관심사 여러 개 구독 | 구독 중인 관심사 전체 반환 |
| 구독 11건 이상 | `user-interest`가 관심사 11개 이상 구독 | 서버 응답 전체 반환 |
| 구독 해제 포함 | 구독 후 해제된 관심사 포함 | 구독 해제 관심사 제외 |
| 비노출 관심사 포함 | 비노출 관심사 포함 | 비노출 관심사 제외 |
| 삭제 사용자 활동 포함 | `user-deleted`가 구독 이력을 가진 뒤 논리삭제됨 | 삭제 사용자 활동 제외 |

### 최근 작성 댓글 조회

| 케이스 | 데이터 구성 | 기대 결과 |
| --- | --- | --- |
| 작성 댓글 없음 | `user-empty`가 댓글을 작성하지 않음 | 빈 목록 반환 |
| 작성 댓글 1건 | `user-comment`가 댓글 1개 작성 | 해당 댓글 반환 |
| 작성 댓글 10건 초과 | `user-comment`가 댓글 11개 이상 작성 | 댓글 작성 시각 기준 최신 10건 반환 |
| 논리 삭제 댓글 포함 | 작성 댓글 중 삭제된 댓글 포함 | 삭제 댓글 제외 |
| 삭제 기사 댓글 포함 | 삭제 또는 비공개 기사에 속한 댓글 포함 | 해당 댓글 제외 |
| 삭제 사용자 작성 댓글 포함 | `user-deleted`가 작성한 댓글 포함 | 삭제 사용자 활동 제외 |
| 동일 시각 댓글 포함 | 같은 작성 시각의 댓글 여러 개 포함 | 보조 정렬 기준으로 안정적으로 반환 |

### 최근 좋아요한 댓글 조회

| 케이스 | 데이터 구성 | 기대 결과 |

| 좋아요 10건 초과 | `user-like`가 댓글 11개 이상 좋아요 | 좋아요 발생 시각 기준 최신 10건 반환 |
| 좋아요 취소 포함 | 좋아요 후 취소된 댓글 포함 | 좋아요 취소 댓글 제외 |
| 삭제 댓글 포함 | 좋아요한 댓글 중 삭제 댓글 포함 | 삭제 댓글 제외 |
| 삭제 사용자 좋아요 포함 | `user-deleted`가 좋아요한 댓글 포함 | 삭제 사용자 활동 제외 |
| 취소 후 재좋아요 | 같은 댓글을 좋아요 취소 후 다시 좋아요 | 최신 좋아요 시각 기준으로 반환 |
| 동일 시각 좋아요 포함 | 같은 좋아요 시각의 댓글 여러 개 포함 | 보조 정렬 기준으로 안정적으로 반환 |

### 최근 조회 기사

| 케이스 | 데이터 구성 | 기대 결과 |

| 조회 이력 없음 | `user-empty`가 기사를 조회하지 않음 | 빈 목록 반환 |

### 물리삭제 검증 데이터

물리삭제 검증 데이터는 삭제 실행 전후 상태를 비교할 수 있도록 대상 ID를 고정한다.

| 도메인 | 데이터 구성 | 기대 결과 |
| --- | --- | --- |
| 사용자 물리삭제 | 물리삭제 후보 사용자가 구독, 댓글 작성, 댓글 좋아요, 기사 조회 이력을 가짐 | 물리삭제 후 해당 userId의 MongoDB activity 문서 제거 |
| 댓글 물리삭제 | 물리삭제 후보 댓글이 작성 댓글과 좋아요 댓글 이력에 포함됨 | 물리삭제 후 댓글 snapshot과 해당 commentId activity 제거 |
| 기사 물리삭제 | 물리삭제 후보 기사가 조회 이력과 댓글 활동의 부모 기사로 사용됨 | 물리삭제 후 기사 snapshot, 기사 조회 activity, 해당 기사 하위 댓글 activity 제거 |

## 성능 검증용 데이터

성능 검증용 데이터는 RDB 조회 병목과 인덱스 효과를 측정하기 위해 사용한다.

데이터 규모는 다음 3단계로 준비한다.

| 규모 | 목적 |
| --- | --- |
| 100k seed scale | 쿼리 구조와 현재 실행 계획 1차 확인 |
| 1m seed scale | 일반 부하 상황에서 조회 병목 비교 |
| 10m seed scale | MongoDB Read Model 적용 필요성 판단 |

대량 데이터는 특정 테이블 하나만 크게 만들지 않고, 활동내역 조회에 실제로 관여하는 관계를 함께 만든다.

```text
사용자
-> 관심사 구독
-> 뉴스 기사
-> 댓글
-> 댓글 좋아요
-> 뉴스 기사 조회 이력
```

대표 사용자 그룹은 다음과 같이 둔다.

| 사용자 그룹 | 목적 |
| --- | --- |
| 활동 없음 사용자 | 빈 목록 응답 비용 확인 |
| 평균 활동 사용자 | 일반적인 조회 비용 확인 |
| 활동 많은 사용자 | 다건 결과 조회와 정렬 비용 확인 |
| 제외 데이터 많은 사용자 | 논리삭제, 취소, 구독 해제 필터 비용 확인 |
| 물리삭제 후보 데이터 | 물리삭제 후 MongoDB Read Model 제거 범위 확인 |

성능 측정 전 확인 항목은 다음과 같다.

```text
- 전체 사용자 수
- 전체 관심사 수
- 전체 뉴스 기사 수
- 전체 댓글 수
- 전체 댓글 좋아요 수
- 전체 기사 조회 이력 수
- 대표 사용자별 구독 관심사 수
- 대표 사용자별 작성 댓글 수
- 대표 사용자별 좋아요 댓글 수
- 대표 사용자별 조회 기사 수
- 논리삭제 사용자 수
- 논리삭제 기사 수
- 논리삭제 댓글 수
- 물리삭제 후보 사용자, 기사, 댓글 ID
```

## 후속 작업 연결

`MID4-123`에서는 데이터 기준을 정의하는 것까지만 완료한다.

실제 데이터 생성 방식은 RDB 스키마와 엔티티가 확정된 뒤 선택한다.

```text
후보 1. Flyway seed SQL
후보 2. 테스트 fixture
후보 3. 별도 seeder
```

대량 성능 데이터 생성과 k6 실행 기준은 MID4-132, MID4-134, MID4-179 측정 문서와 [RDB 조회 성능 측정 시나리오](./08-rdb-performance-test-scenarios.md)에서 다룬다.

MongoDB Read Model 데이터 생성은 RDB 성능 검증 후 병목 기능이 선정되고 후속 적용이 확정된 뒤 별도 티켓에서 다룬다.

## 완료 기준

```text
- 4개 조회 기능별 정확성 검증 케이스가 정의되어 있다.
- 구독 중인 관심사는 서버 응답에서 전체 반환함이 명시되어 있다.
- 최근 작성 댓글, 최근 좋아요한 댓글, 최근 조회 기사는 최대 10건 제한 대상임이 명시되어 있다.
- 사용자, 기사, 댓글 논리삭제 제외 케이스가 포함되어 있다.
- 사용자, 기사, 댓글 물리삭제 후 MongoDB Read Model 제거 기준이 포함되어 있다.
- 취소, 구독 해제 같은 제외 케이스가 포함되어 있다.
- 100k / 1m / 10m seed scale 성능 검증용 데이터 규모 기준이 정리되어 있다.
- MID4-132, MID4-134, MID4-179 측정 결과와 연결해 MongoDB 재검토 조건을 판단할 수 있다.
```
